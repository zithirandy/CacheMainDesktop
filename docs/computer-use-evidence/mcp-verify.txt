windows-mcp 能力验证原始结果（2026-10-06 更正轮）
====================================================

执行方式说明（本会话工具可见性受限，以下为如实记录）
----------------------------------------------------
本更正轮的 Claude 会话仍是从父目录 F:\原E盘 启动的，其会话内工具清单里没有
mcp__windows-mcp__* 函数；定向等待返回原文：

    WaitForMcpServers(servers=["windows-mcp"]) ->
    ready: false
    Unknown (no MCP server with this name is configured): windows-mcp

根因诊断（配置层证据，非猜测）：
  1) 在项目根 F:\原E盘\CacheMainDesktop 下执行 `claude mcp get windows-mcp`：
         windows-mcp:
           Scope: Local config (private to you in this project)
           Status: ✔ Connected
           Type: stdio
           Command: uvx
           Args: windows-mcp serve
  2) 在父目录 F:\原E盘 下执行同一命令：
         No MCP server named "windows-mcp". (Configured servers: chrome-devtools,
         codegraph, gitnexus, pencil, ...)
  3) ~/.claude.json 的项目条目核对：仅 "F:/原E盘/CacheMainDesktop" 条目下挂有
     windows-mcp（Local scope 按会话启动目录解析）。
  => 上一轮与本轮主会话的「工具不可用」均为会话启动目录导致的服务器未加载，
     属会话可见性问题；环境层面 windows-mcp 已配置且可连接（与更正方留档一致）。

因此本轮的 4 项工具探测改由「项目根目录起嵌套 claude -p + stream-json 落盘原文」
执行（与更正方验证方法一致；stream-json 中的 tool_result 为未经模型改写的原文）。
注意：嵌套 -p 会话首次运行时 windows-mcp 处于 pending（uvx 冷启动慢），模型未等待
即报不可用；正确做法是先调用内置 WaitForMcpServers 阻塞等待就绪再调用工具。
本轮全部有效探测均带该等待步骤，等待返回原文：

    ready: true
    Connected (their tools are now available — call them directly): windows-mcp

二、App —— 可调用；无「列出窗口」模式；本环境切换前台失败（原文留档）
----------------------------------------------------
工具实际只有 launch / launch_executable / resize / switch 四种模式，没有列出
窗口的动作。两次调用原文：

(a) 无 name 参数（探测模式时）：
    # INPUT: {"mode":"switch"}
    Error calling tool 'App': Error switching app: expected string or bytes-like object, got 'NoneType'

(b) 正确参数 mode=switch + name=CacheMainDesktop（应用正在运行）：
    # INPUT: {"mode":"switch","name":"CacheMainDesktop"}
    Error calling tool 'App': Failed to bring CacheMainDesktop to the foreground within 1 second.

(b) 说明工具按名称定位到了应用并执行了切换动作，卡在 OS 前台激活 1 秒超时
（本会话跑在 RDP 会话内，后台进程抢占前台受系统限制；此为环境性失败模式，
是否在控制台会话可成未验证）。「确认窗口存在」由 Snapshot 的 Opened Windows
表承担（见 mcp-snapshot-cachemaindesktop.txt），窗口级枚举可靠。
