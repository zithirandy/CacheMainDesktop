## 2. 各项修复说明

### D2 — Redis 导入 TTL 单位错误（严重）

**根因**：`Helpers::export()` 写出的是秒（Redis `TTL`），而 `RESTORE` 命令的 TTL 参数单位是**毫秒**。
`RedisTrait.php` 把秒直接透传给了 `restoreKeys()`，于是每个导入的键寿命被缩短 1000 倍
（实测：2000 秒的键导入后只剩 2 秒）。

**修复**：
```php
$milliseconds = $ttl > 0 ? $ttl * 1000 : 0;
return $this->redis->restoreKeys($key, $milliseconds, (string) hex2bin($value));
```
负值统一按"无过期"处理（与 Redis 语义一致，同时消除了原先 `-1` 与 `0` 混用的歧义）。

**验证**（`scripts/check-redis-restore-ttl.php`，直接驱动应用自己的 `Compatibility\Predis::restoreKeys`）：
```
source key TTL (what export writes) : 2000s
restoreKeys(key, 2000000, payload) -> true , TTL = 2000s   <- 修复后
restoreKeys(key, 2000,    payload) -> true , TTL = 2s      <- 旧参数，复现了 1000 倍缩短
PASS
```

### D5 — 窗口状态导致主内容区不可用（严重）

**根因**：`clampToScreen()` 只保证窗口不超出显示器、不小于 `MIN_WIDTH`，但**不保证内容区可用**。
`window-state.json` 里一份来自其它显示配置的几何（`1289x842`）被原样还原后，实测渲染视口只有
607×685，扣除固定 240px 侧边栏，主内容区仅 **339px**，键列表与表单无法使用。清除该文件是当时唯一的解法。

**修复**：新增 `correctionForUsableContent(bounds, viewport, workArea)`，在窗口加载完成后**实测渲染视口**
（而非猜测几何换算），若内容区不足 600px 就按比例纠正窗口尺寸并回写状态，使下次启动即正常。
内置一次性护栏：同一宽度只纠正一次，显示器的物理限制不会被反复对抗。

**验证**（`test/window-state.test.mjs` 新增 6 项，全部通过）：
- 健康窗口不被改动
- 复现的 1289→607 单位错配被纠正为 ≥1782px
- 同单位下的窄窗口只补足差额，且不低于 `MIN_WIDTH`
- 显示器本身过小时不强行放大
- 同一宽度不会触发第二次纠正（防死循环）
- 非法输入返回 `null` 而非抛错

### D4 — Memcached 编辑静默清零 TTL（中等偏重）

**根因有两层**，第二层是修复过程中才发现的：

1. `MemcachedKeyView::form()` 的 `expire` 取自 URL 的 `ttl` 参数，缺失时退化为 `0`；
   而 `saveKey()` 会把 `0` 当作"永不过期"写回 —— 用户只改值、保存，键就变成永久键。
2. **`PHPMem::getKeyMeta()` 的两条代码路径返回值单位不一致**：
   旧版回退路径（`stats items`）会减去 `time()` 得到剩余秒数，而 1.5.19+ 的 `me` 命令路径
   **直接返回原始值**。实测 memcached 1.6.45 的 `me` 返回 `exp=600`（已是剩余秒数），
   但当时无任何归一化，导致键详情页把数值当成时长显示、编辑表单预填 0。

**修复**：
- 抽出 `PHPMem::normaliseExpiry($data, $now, $absoluteExp)`，显式区分两种来源
  （`me` 已是剩余时长 → 原样返回；旧路径是绝对 epoch → 减去当前时间），两条路径统一走它；
- `form()` 用哨兵默认值区分"URL 未给 ttl"与"ttl=0"，缺省时预填真实剩余 TTL。

**验证**：
- 单测 11 项全通过（`scripts/test-php-normalise-expiry.php`），覆盖永久键、`me` 时长、epoch 换算、已过期、无字段等
- 端到端：给键设 900 秒 TTL → 编辑表单 **预填 900**（修复前为 0）
- 键详情页 TTL 正确显示为 `9 minutes 54 seconds` 并正常倒数

### D1 — zset 无法输入小数分数（中等）

**根因**：`type="number"` 的默认 `step=1`，浏览器原生校验拦下 `42.5`；后端其实一直是
`(float) Http::post('score')` 并调用 `zAdd`，纯属前端限制。

**修复**：给 score 输入加 `step="any"`，并补一句提示 `Fractions are allowed, e.g. 1.5.`。

**验证**：渲染结果含 `step="any"`。

### D3 — 导入失败无反馈（中等）

**根因**：`Helpers::import()` 的 `catch (JsonException) {}` 是空块，非法文件被完全吞掉；
且原实现从不返回结果，调用方无从得知发生了什么。

**修复**：
- `import()` 改为返回 `{imported, skipped, failed, error}`，不再吞异常；
- 新增 `importMessage()` 生成人话摘要、`takeImportResult()` 读取一次性会话 flash；
- Redis 与 Memcached 两个面板都展示结果（失败用 error 色，成功用 success 色）；
- **跳过已存在的键会明确报"skipped (already present)"** —— 不覆盖是正确行为，但原先完全静默。

**修复过程中的额外发现**：单测暴露出 `{"nope":true}` 这类单个 JSON 对象会被当成一条无字段条目、
误报为"1 could not be restored"。已加 `array_is_list()` 检查，改为提示"does not contain a list of keys"。

**验证**（`scripts/test-php-import.php`，8 项全通过）：非法 JSON、非列表对象、空列表、正常导入、
已存在跳过、字段缺失、写入失败、无文件 —— 每种情形都返回可读结果。

### O6 — expire 语义未说明（轻微）

Redis 面板原先只写 `-1 removes expiration (default).`，但 `0` 同样等于永久，用户无从得知。
两个面板文案已按各自协议改写：
- Redis：`Seconds from now. 0 or -1 means the key never expires (-1 is the default).`
- Memcached：`Seconds from now, max 30 days. 0 means the key never expires.`

### O9 — 大值不折叠（轻微）

`partials/view_key.twig` 的值容器只有 `overflow-auto`、无高度上限，100KB 值会把整页撑长。
已改为 `overflow-auto max-h-96`，与项目里 `analysis.twig`、`preload.twig` 的既有写法一致。

## 5. 顺带发现的两个工程问题（值得记入文档）

1. **`dist/win-unpacked/resources/webapp` 是构建期副本，不是链接**。
   修改仓库里的 `webapp/` 对已打包的应用**没有任何影响**，而且很容易误判（两边路径都叫 `webapp/`）。
   这是本次排查中真实踩到的坑，已通过 `scripts/sync-webapp-to-dist.mjs` 缓解，建议写入 `CLAUDE.md` 的 gotchas。

2. **`Helpers::alert()` 的提示不会出现在原始 HTML 里**。
   `layout.twig` 只提供一个空的 `<div id="alerts">`，提示由脚本注入。
   用 HTTP 抓页面来判断提示是否存在会得到假阴性 —— 必须检查实时 DOM。
