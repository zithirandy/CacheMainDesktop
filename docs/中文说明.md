## 二、项目简介

phpCacheAdmin 是**单文件入口 + 零运行时依赖**的 Web 管理面板：

- **不需要数据库**、**不需要 Composer** 即可运行（`README.md` 明确说明）。
  原因见第四节：它把 `twig.phar` 与 `predis.phar` **直接打包进仓库**。
- **Docker ready**：仓库自带 `Dockerfile` 与 `docker-compose.yml`，官方也发布了镜像。
- 定位是"**装在自己机器/内网上的运维面板**"，而不是 SaaS。

**设计上值得注意的两点**：

1. **五种缓存统一到一个界面**，且每个面板的深度不同——
   Redis 面板做得最完整（含集群、Sentinel、ACL、Profiler、Console、Metrics），
   Memcached 面板次之（含 Watcher、Console、Slabs/Items），
   APCu / OPcache / Realpath 则是 PHP 自身的缓存。
   另有独立的 **Server 面板**展示 phpCacheAdmin 所在机器的 PHP 版本与 CPU/内存/磁盘。
2. **有明确的"安全默认值"意识**：提供只读模式、控制台命令黑名单、CSP 等安全响应头、
   以及**首次使用时主动提示你设置登录用户**（见第七节，这一点很重要）。

## 三、核心功能

### 3.1 通用能力

- 清爽的响应式界面，**带深色模式**。
- **可在多个已配置的 Redis / Memcached 服务器之间切换**。
- key 列表支持**表格视图或树状视图**（按可配置的分隔符分组）。
- **备份与恢复**数据。
- 跨缓存**快速搜索 key**。
- 在**弹窗（modal）**中查看 key 详情，不必离开列表。
- 值可按**格式化 / 原始 / 十六进制转储**三种方式查看。
- **自动套用转换器**（gzip、zlib…）与**格式化器**（`unserialize`）。
- 可选**登录页**（在 `authusers` 中定义用户后启用）。
- **只读模式**：隐藏并阻止一切破坏性操作。
- **运行不需要 Composer**、**Docker ready**。

### 3.2 Redis 面板（含 Valkey / KeyDB）

- 同时兼容 **phpredis** 与 **Predis** 两种客户端。
- 查看 / 新增 / 编辑 / 删除 key，**支持全部 Redis 数据类型，含 vector sets**。
- 在 key 的**子项内搜索**（hash 字段、set/list/sorted set 成员）。
- **Stream 消费者组**：消费者、待处理条目（pending）、lag、以及等待确认最久的条目。
- **Keyspace 分析**、以及服务端自行跟踪的每个 key 的体积分布（**Redis ≥ 8**）。
- **Latency**：延迟监视器记录的事件与历史、按命令的延迟百分位、`LATENCY` / `MEMORY DOCTOR` 建议。
- **Clients**：已连接客户端列表（空闲时间、内存、最后命令），**可断开任意连接**。
- **Profiler**：通过 `MONITOR` **实时**观察命令执行；**在集群中同时观察所有节点**。
- **Console**：交互式执行 Redis 命令，**按服务器持久化命令历史**。
- **PUB/SUB**：浏览频道、订阅与发布消息。
- **Metrics + 健康检查**：内存、命中率、驱逐、客户端、持久化、复制。
- **Cluster 支持**、**Sentinel 支持**、**ACL 支持**。
- 详细的服务器统计（命令调用、内存、运行时长、连接数等）。
- 查看 **slowlog** 排查性能问题。
- key 检索**同时支持 `SCAN` 与 `KEYS`**。

### 3.3 Memcached 面板

- **使用自研客户端，因此不需要 `memcache`/`memcached` PHP 扩展。**
- 查看 / 新增 / 编辑 / 删除 key。
- **Keyspace 分析**，以及**缓存中每个 item 的体积分布**——
  **前提是服务端以 `-o track_sizes` 启动**。
- **Watcher**：实时观察服务端对每个 key 做了什么——
  读、写、驱逐、删除与连接事件，直接来自**服务端自己的日志流**。
  **按服务端版本提供能力**：watcher 需 **1.4.26**，连接事件需 **1.6.11**，删除事件需 **1.6.20**。
- **Connections**：已打开连接列表及其状态与空闲时间。
- **Console**：交互式执行 Memcached 命令，按服务器持久化历史。
- **Metrics + 健康检查**。
- **Server Stats**：运行时长、内存占用、连接数等。
- **Slabs & Items** 信息。
- **Commands Stats**。

### 3.4 PHP 缓存面板

- **APCu**：查看/编辑/删除用户缓存条目；查看缓存信息与内存统计；
  **内存图（memory map）**展示每个共享内存段的空闲内存是"一整块"还是"碎屑"；健康检查。
- **OPcache**：查看与**失效**已缓存脚本；内存占用/命中率/缓存 key 统计；
  **Treemap 可视化**（按内存占用）；**Preload 列表**；
  **Warmup**——把整个目录编译进缓存（**部署后立刻预热很有用**）；健康检查。
- **Realpath Cache**：查看与清除 realpath 缓存条目（含 TTL 与内存占用）；
  针对缓存大小、过期条目与 TTL 的健康检查，
  **并会警告 `open_basedir` 会导致该缓存完全失效**。
- **Server 面板**：phpCacheAdmin 所在机器的 PHP 版本与配置、已加载扩展、`phpinfo()`、CPU/RAM/磁盘占用。

### 3.5 自定义面板（扩展点）

README 给出了实现自定义面板的示例项目：
[FileCache-Dashboard](https://github.com/RobiNN1/FileCache-Dashboard)（配合 `robinn/cache`）。

## 四、技术栈

- **语言**：PHP（`composer.json` 要求 **PHP >= 8.2**）。
  **需要 PHP 7.4 的用户请使用 [v1 分支](https://github.com/RobiNN1/phpCacheAdmin/tree/v1.x)。**
- **模板引擎**：**Twig**（`twig/twig: ^3.29`）—— 但**以 `twig.phar` 形式直接打包进仓库**，
  这就是"不需要 Composer"的原因。
- **Redis 客户端**：`phpredis`（扩展）**或** `Predis`——后者同样以 `predis.phar` 打包进仓库。
- **前端**：**Tailwind CSS**（`package.json` 存在，属**开发期**依赖；仓库已含编译产物于 `assets/`）。
- **自研 Memcached 客户端**：直接实现协议，**不依赖 PHP 的 memcache(d) 扩展**。
- **静态分析 / 测试**：**PHPStan**（`phpstan.neon`）+ **PHPUnit**（`phpunit.xml`，`tests/`）。
- **扩展依赖（可选，按面板启用）**——来自 `composer.json` 的 `suggest`：
  - `ext-redis` —— Redis 面板需要（或改用 Predis）
  - `ext-sqlite3` —— **Metrics 指标功能需要**
  - `ext-apcu` —— APCu 面板需要
  - `ext-zend-opcache` —— OPCache 面板需要
  - `ext-zlib` —— `gz*` 系列编码/解码需要
- **配置方式（三种，可混用）**：`config.php` 文件 / `PCA_` 前缀环境变量 / `.env` 文件。
- **容器**：基于 **Alpine 3.23** + **nginx** + **php85-fpm**（见 `Dockerfile`）。

## 六、使用方式（安装）

### 方式 A：Docker 官方镜像（推荐，最省事）

官方镜像已发布在 Docker Hub：`robinn/phpcacheadmin`（README 给出的单行命令）：

```bash
docker run -p 127.0.0.1:8080:80 -d --name phpcacheadmin \
  -e "PCA_REDIS_0_HOST=redis_host" \
  -e "PCA_REDIS_0_PORT=6379" \
  -e "PCA_MEMCACHED_0_HOST=memcached_host" \
  -e "PCA_MEMCACHED_0_PORT=11211" \
  robinn/phpcacheadmin
```

然后打开 `http://127.0.0.1:8080`。

> **注意端口绑定**：官方示例用的是 **`127.0.0.1:8080:80`**，
> 即**只监听本机回环地址**。这是**有意的安全默认值**——
> 因为**未配置登录用户前，任何人打开页面都能读写你所有缓存数据**（见第七节）。
> **不要图省事改成 `-p 8080:80` 暴露到局域网/公网。**

### 方式 B：Docker Compose（仓库自带，用于开发）

仓库的 `docker-compose.yml` 是**开发用途**（`build: .` 本地构建，
且把整个仓库目录 `./:/var/www/html/` 挂载进容器）：

```yaml
services:
  phpcacheadmin:
    build: .
    ports:
      - "127.0.0.1:8080:80"
    volumes:
      - "./:/var/www/html/"
    environment:
      - PCA_REDIS_0_HOST=redis
      - PCA_REDIS_0_PORT=6379
      - PCA_MEMCACHED_0_HOST=memcached
      - PCA_MEMCACHED_0_PORT=11211
    depends_on:
      - redis
      - memcached
  redis:
    image: redis:8-alpine
  memcached:
    image: memcached:alpine
```

**这个文件很适合"本地起一套 Redis + Memcached 来试用"**（一条命令同时拉起三个容器）。
但注意它 `build: .` 是**从源码构建镜像**，会慢一些；
若只想跑预构建镜像，把 `build: .` 换成 `image: robinn/phpcacheadmin`。

```bash
docker compose up -d
# 打开 http://127.0.0.1:8080
```

**用挂载方式时要注意 `tmp/`**：因为把宿主机目录整个挂进了容器，
容器里镜像自带的 `tmp/` 会被宿主机目录覆盖，**而宿主机上并没有这个目录**（`.gitignore` 忽略了它）。
**请先手动创建，否则 metrics/Twig 缓存会写不进去**：

```bash
mkdir -p tmp/metrics tmp/twig
# Linux 下还需让容器内 www-data（UID 82）可写：
# sudo chown -R 82:82 tmp
```

### 方式 C：传统 PHP 部署（不用 Docker）

1. **准备环境**：PHP >= 8.2 + 一个 Web 服务器（nginx 或 Apache）。
   确保装了需要的扩展（按你要用的面板）：
   ```bash
   # 以 Debian/Ubuntu 为例
   sudo apt install php8.2-fpm php8.2-mbstring php8.2-xml php8.2-sqlite3
   sudo apt install php8.2-redis        # 或用打包的 Predis，二选一
   sudo apt install php8.2-apcu         # 仅 APCu 面板需要
   # OPCache 通常随 PHP 自带（ext-zend-opcache）
   ```

2. **放到 Web 目录**（两种来源）
   - **下载 release 压缩包**：`https://github.com/RobiNN1/phpCacheAdmin/releases`，
     解压到 Web 目录即可（**不需要 Composer，不需要数据库**）。
   - **或直接用本仓库这份克隆**（把源码目录整体作为站点根目录）。

3. **建 `tmp/` 并给写权限**（**关键步骤，最容易漏**）
   ```bash
   mkdir -p tmp/metrics tmp/twig
   sudo chown -R www-data:www-data tmp     # 换成你 Web 服务器的运行用户
   ```

4. **配置**（可选）
   ```bash
   cp config.dist.php config.php    # README 明确要求：不要直接改 config.dist.php
   # 然后编辑 config.php，或用 PCA_ 环境变量，或复制 .env.example 为 .env
   ```
   - 若用 `.env` 文件，需要 **vlucas/phpdotenv**：`composer require vlucas/phpdotenv`
     （这是**唯一需要 Composer 的场景**）。
   - **环境变量优先级高于 `.env` 文件**，所以可以运行时覆盖。

5. **打开浏览器**访问站点根目录即可。

**PHP 内置服务器快速试跑**（仅本地验证，不要用于生产）：
```bash
php -S 127.0.0.1:8080
# 打开 http://127.0.0.1:8080
```

## 七、注意事项（务必阅读）

### 7.1 ⚠️ 默认没有任何认证——这是最大的风险点

`README.md` 的 **Access** 一节原文警告（意译）：

> **在你于 `authusers` 中定义用户之前，没有任何认证。
> 因此任何能打开这个页面的人，也能读取、修改和删除所有已配置服务器里的全部数据。**

**这是本工具最关键的安全设定。** 请务必三选一（或叠加）：

1. **只在可信网络内使用**（且如官方示例那样只绑定 `127.0.0.1`）；
2. **启用登录页**——在 `config.php` / 环境变量中定义 `authusers`；
3. **在 Web 服务器层面加认证**（nginx `auth_basic` 等）。

**再叠加 `readonly`** 则只保留面板的只读部分。

**关于 `authwarning` 的设计（需要知情）**：
在未定义用户时，面板上会弹出一个提示，**并且允许你直接从该提示设置第一个用户**——
条件是**Web 服务器对 `config.php` 有写权限**。
密码以 `password_hash()` 哈希存储，**该会话立即登录**。
关闭提示会隐藏一个月，`authwarning => false` 永久关闭。
> **这很方便，但也意味着：如果你把未设认证的实例暴露出去，
> 攻击者可以直接通过这个提示给自己开一个管理员账号。**
> 若不需要此便利，建议预先定义好 `authusers`，或设 `authwarning => false`。

**密码建议用哈希而非明文**（`.env.example` 明确提示"该文件对一切以 Web 服务器身份运行的进程可读"）：
```bash
php -r 'echo password_hash("your-password", PASSWORD_DEFAULT);'
# 把输出填进 PCA_AUTHUSERS={"admin":"$2y$12$..."}
```

### 7.2 功能限制

- **Memcached 不支持 SASL**。README 在 Requirements 中明确说明原因：
  **"SASL is not supported because there is no way to get the keys."**
  （启用 SASL 后无法枚举 key，因此无法管理。）**如果你的 Memcached 开了 SASL，本工具无法使用。**
- **Memcached 的 Keyspace 体积分析**需要服务端以 **`-o track_sizes`** 启动，否则拿不到。
- **Memcached Watcher 依赖服务端版本**：watcher 需 **≥1.4.26**，连接事件需 **≥1.6.11**，
  删除事件需 **≥1.6.20**；README 说明"只提供你的服务端版本所支持的"。
- **Redis ≥ 8** 才有服务端自track 的每 key 体积分布。
- **phpredis 需 ≥ 5.3.7**（PHP 8.2 的最早构建）；更旧的话把 `redisoptions.client` 设为 `predis`。
- **Metrics 功能需要 `sqlite3` 扩展**。
- **不需要全部面板都启用**（README 明确说明）——
  你可以只保留 `Redis` 与 `Memcached` 两个面板，把 `dashboards` 列表裁到最小，减小攻击面。

### 7.3 部署注意事项

- **必须新建 `tmp/` 并给写权限**（见第五节）。它是 `tmpdir` / `metricsdir` / `twigcache` 的默认位置。
  官方 nginx 配置里还会 `location ~ ^/tmp/ { return 404; }` **显式屏蔽对 tmp 的 Web 访问**——
  **如果你自己配 nginx/Apache，建议照做**，避免 metrics 数据库被直接下载。
- **环境变量前缀是 `PCA_`**，数组用 `_` 展开，例如 `PCA_REDIS_0_HOST`。
  **要加第二个服务器就把 `0` 改成 `1`**。
- **不要编辑 `config.dist.php`**，它是模板（升级会覆盖）；请复制为 `config.php`。
  `.gitignore` 已正确忽略 `config.php` 与 `.env`，**避免凭据误入版本库**。
- **Cronjob 采集指标**（README 提供）：面板不打开时也能持续采集
  ```
  https://example.com/phpCacheAdmin/?dashboard=redis&server=0&ajax&metrics
  https://example.com/phpCacheAdmin/?dashboard=memcached&server=0&ajax&metrics
  ```
  启用认证后，需在 `config.php` 设 `authtoken` 并在 URL 后加 `&token=…`；
  也可用 `X-Pca-Token` 请求头（**不会进入 access log，更安全**）。
  README 强调 **token 要足够长随机**：`php -r 'echo bin2hex(random_bytes(32));'`。
- **安全响应头默认开启**（`securityheaders => true`，含 CSP、X-Frame-Options、
  X-Content-Type-Options、Referrer-Policy）。**除非有明确理由，不要关掉。**
- **控制台命令黑名单**：可在 `redisoptions.blockedcommands` /
  `memcachedoptions.blockedcommands` 里追加要拒绝的命令
  （配置模板的注释里给出的候选是 `CONFIG SET`、`CONFIG REWRITE`、`REPLICAOF`、`SLAVEOF`、
  `MIGRATE`、`RESTORE`、`SAVE`；Memcached 侧是 `flush_all`、`stats reset`）。
  > 这是**重要的**：本工具的控制台相当于把 `redis-cli` 暴露到网页上，
  > **建议至少把 `FLUSHALL`/`FLUSHDB`/`CONFIG SET` 这类高危命令加进黑名单。**
