# 使用指南（实测版）

> 本文基于对 `F:\原E盘\CacheMainDesktop` 的实际运行验证整理。
> 验证环境：Windows 10/11，Node v24.18.0，npm 12.0.2，仓库 HEAD `77ac756`。
> 结论中被标为「已实测」的项目，都是本次真实跑通的结果，不是照抄 README。

## 一、这个项目是什么

**CacheMainDesktop 是一个 Windows 桌面版的 Redis / Memcached 图形化管理工具。**

它不是从零写的，而是给开源 Web 项目 [phpCacheAdmin](https://github.com/RobiNN1/phpCacheAdmin)（v2.7.2，MIT）
套了一个 Electron 外壳：

```
Electron 窗口 ── http://127.0.0.1:<随机端口> ──> php/php.exe -S
                                                  └─ webapp/（phpCacheAdmin 改版，含 predis.phar）
```

关键设计：**自带 PHP 运行时**。所以对最终用户来说不需要装 PHP、不需要 Composer、不需要数据库，
解压即用。连接信息由桌面外壳通过 `PCA_*` 环境变量注入给 PHP，PHP 核心几乎未改动。

与上游 phpCacheAdmin 的差异：

| 差异 | 说明 |
| --- | --- |
| 侧边栏 UI | 重写了 `webapp/templates/layout.twig`，做成 ARDM 风格侧边栏（已实测） |
| 连接管理 | 新增独立的 Connections 窗口，连接列表存在本地 JSON，不走 `config.php`（已实测） |
| 入口鉴权 | 去掉了登录页（`authusers => []`、`authwarning => false`）；后端只绑 `127.0.0.1` 随机端口 |
| 面板收敛 | 只保留 **Server / Redis / Memcached** 三块；APCu、OPCache、Realpath 面板已在 `webapp/config.php` 中注释掉 |

被注释掉的原因写在 `README.md` 里：那三个面板监控的是「运行它自己的那个 PHP 进程」，
在这里就是自带的那个后端进程，对你的生产服务器没有意义。

## 二、最快用法：直接运行已经打包好的绿色版（推荐）

**已实测可用。** 打包产物就在仓库里，不用编译：

```
dist\win-unpacked\CacheMainDesktop.exe
```

直接双击运行即可。整个 `dist\win-unpacked\` 目录就是完整程序（约 246 MB 的 exe + `resources\php\` + `resources\webapp\`），
把它复制到任何有写权限的位置都能跑。

从命令行启动：

```powershell
Start-Process "F:\原E盘\CacheMainDesktop\dist\win-unpacked\CacheMainDesktop.exe"
```

启动后会自动：起一个 `php.exe -S 127.0.0.1:<随机端口>` 后端 → 等它就绪 → 打开窗口。
实测后端确实以随机端口起来（本次为 51795），窗口标题正常显示 `Server - CacheMainDesktop`。

### 首次使用流程

1. 打开左侧栏底部的 **Connections** 按钮 → 弹出连接管理窗口。
2. 点右上角 **New** → 填写连接 → 注意这里是**两步操作**：
   - 表单底部按 **Apply** → 只是「暂存」到列表，状态栏提示 `Not saved yet - press Save & Apply.`
   - 再按窗口底部 **Save & Apply** → 才真正写入磁盘并**重启 PHP 后端**（约 1 秒），主窗口随之刷新。
3. 回到主窗口，切到 **Redis** / **Memcached** 面板，左下角 `SERVER` 下拉框里选择刚配的连接。

**已实测**：上述流程走通后，`connections.json` 正确落盘，PHP 后端进程被换成了新的 PID（说明重启生效），
连接出现在 Redis 面板的服务器下拉框中。

第 2 步那个「Apply 再 Save & Apply」是最容易让人以为「保存没反应」的地方，务必注意。

### 数据存在哪里

全部在 `%APPDATA%\CacheMainDesktop\`：

| 文件 / 目录 | 内容 |
| --- | --- |
| `connections.json` | 连接列表（**密码是明文**） |
| `settings.json` | 自动生成的 metrics hash |
| `window-state.json` | 窗口位置尺寸 |
| `runtime.json` | 后端 php.exe 的 pid/端口，用于下次启动清理残留进程 |
| `data\metrics\`、`data\twig\` | 指标数据库与 Twig 模板缓存 |

想「恢复出厂设置」就关掉程序，删掉 `%APPDATA%\CacheMainDesktop` 整个目录。

## 三、开发用法

```bash
npm install          # electron / electron-builder / tailwind CLI
npm run fetch-php    # 下载便携版 PHP 到 php\（带 sha256 校验）
npm run build:css    # 从 src.css 生成 webapp\assets\css\styles.css
npm start            # 启动
```

**当前仓库的 `npm install` 是没跑完的**：`node_modules\electron\` 里只有 JS 包装层，
缺 `dist\electron.exe`（`path.txt` 也是空的），所以**现在直接 `npm start` 会失败**。
重新跑一次 `npm install` 让它执行 postinstall 下载即可（Electron 44.4.5 的压缩包已经在
`%LOCALAPPDATA%\electron\Cache\` 里缓存过了，不用重新下载）。

改完 Twig 模板后**必须**同时做两件事，否则改不出效果：

```bash
rm -rf webapp/tmp/twig && npm run build:css
```

因为 Twig 缓存不会自动刷新，而且新的 Tailwind 工具类要从模板里扫描生成。

### 测试

```bash
npm test        # 单元测试：连接 ↔ PCA_* 环境变量映射、窗口状态
npm run smoke   # 无头启动真实 PHP 后端并检查各页面
```

**已实测全部通过**：`npm test` → 31 个用例全过；`npm run smoke` → 7 项检查全过
（根页面 200、Redis/Memcached 面板渲染出注入的连接名、AJAX 面板返回 JSON、样式表可访问）。

## 四、重新打包

```bash
npm run dist
```

`predist` 会先跑 `fetch-php` 和 `build:css`，再交给 electron-builder。
产物是 `dist\CacheMainDesktop 1.0.0.zip`（便携版）。

注意 `fetch-php` 有一个**严格版本钉死**：`PINNED_VERSION = '8.5.11'`，
如果 windows.php.net 上 8.5 系列已经出了更新的补丁版，它会直接失败并提示你
「要么有意识地升 `PINNED_VERSION`，要么加 `--allow-drift`」。这是有意的设计，不是 bug。

## 五、能力范围

Redis 面板做得最深：key 增删改查（支持全部数据类型含 vector sets）、
子项搜索、Stream 消费者组、Keyspace 分析、Latency、Clients、Profiler（MONITOR 实时）、
Console（游标历史持久化）、PUB/SUB、Metrics 与健康检查、Cluster / Sentinel / ACL、slowlog。

Memcached 面板：key 增删改查、Keyspace 与体积分布、Watcher（实时观察服务端日志流）、
Connections、Console、Metrics、Server Stats、Slabs & Items。

Server 面板：PHP 版本与配置、已加载扩展、`phpinfo()`、CPU / 内存 / 磁盘占用。

几个需要知道的限制：

- **Memcached 不支持 SASL**。因为开了 SASL 就无法枚举 key，上游明确说明。
- Memcached 的体积分析需要服务端以 `-o track_sizes` 启动。
- Memcached Watcher 需要服务端 ≥ 1.4.26；连接事件需 ≥ 1.6.11；删除事件需 ≥ 1.6.20。
- **Redis 走的是 Predis（`webapp\predis.phar`），不是 phpredis 扩展。**
  自带的 `php.ini` 只启用了 `mbstring`、`openssl`、`pdo_sqlite`。
  实测界面上显示的是 `Predis v3.6.1`，属于预期行为，不需要去补 `php_redis.dll`。
- Metrics 功能依赖 `pdo_sqlite`（已启用）。

## 六、安全模型

- 后端只绑定 `127.0.0.1` 的随机端口；`webapp/index.php` 里有 DNS-rebinding 防护，
  会拒绝来源 Origin 或 Host 头不对的请求。
- **没有登录页**。这是有意的设计——窗口本身就是入口，而端口只在回环地址上随机开放。
  但**本机上的其它进程只要能猜到端口就能访问**，这一点与其它本地开发工具是同一个信任边界。
- **连接密码以明文存放在 `%APPDATA%\CacheMainDesktop\connections.json`**（未用 DPAPI 加密）。
  请把它当普通凭据文件对待。
- Console 面板相当于把 `redis-cli` 搬到了网页上。

## 七、已知问题与排查

### 1. 程序启动后立刻静默退出，没有窗口

**先检查环境变量 `ELECTRON_RUN_AS_NODE`。**

如果它被设成了 `1`，Electron 会退化成纯 Node 解释器，
于是 `package.json` 的 `main.mjs` 被当普通脚本加载，遇到 `import from 'electron'` 直接报错退出，
**不弹任何错误框**——看起来就是「双击没反应」。

本次排查就是踩到了这个坑（该变量是从上游工具链继承下来的，不是项目或机器的问题）。
清除后程序一切正常：

```powershell
Remove-Item Env:\ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
```

如果这个变量来自某个全局配置，记得在系统环境变量里也去掉。

### 2. `Server` 面板里 php.ini 路径显示成乱码

因为项目放在 `F:\原E盘\` 这样的非 ASCII 路径下，
`Server` 面板的 `Loaded php.ini file` 一行会显示成 `F:\ԭE��\...`。

**结论：纯显示问题，功能完全不受影响。** 实测数据如下。

**根因（已用原始字节确认）**：PHP 内部处理 Windows 路径时用的是系统 ANSI 代码页
（本机为 CP936 / GBK），输出到页面时没有转成 UTF-8，而页面声明的是 `<meta charset="utf-8">`。
抓到的原始字节是：

```
46 3A 5C  D4 AD  45  EF BF BD EF BF BD  5C 43 ...
F  :  \   原     E   （U+FFFD）（U+FFFD）  \  C
```

`原` 的 GBK 字节是 `D4 AD`，而它正确的 UTF-8 字节应该是 `E5 8E 9F` —— 两者不一致，
所以浏览器按 UTF-8 解码就显示成乱码；`盘` 更是已经在上游被替换成了 U+FFFD 替换字符，无法还原。
不是 `php.ini` 文件本身的问题（该文件已实测无 BOM、内容字节正常）。

**功能无影响的实测证据**：

| 检查项 | 结果 |
| --- | --- |
| `php.exe --ini` 显示 Loaded Configuration File | 正确指向该路径 |
| 自定义配置项是否生效（`memory_limit=256M`、`expose_php=false`、`error_log=stderr`、`date.timezone=UTC`、`extension_dir=ext`） | **全部生效**（读不到 ini 会退回默认值，故可反证已加载） |
| 把 tmp / metrics / twig 放到含中文的目录（`webapp\tmp\中文测试\`） | 首页、Redis、Memcached、AJAX、metrics 采集**全部 200**，PHP 日志**零 Warning / 零 Fatal** |
| 中文目录下的产物 | Twig 缓存（7 个 `.php`）、`redis_metrics_*.db`(16 KB sqlite)、`pca_server_resources_*.json` 均正确生成 |
| 全页扫描中文路径出现的位置 | **只有 `Loaded php.ini file` 这一处** |

**如果想彻底消除**：把程序移到纯英文路径即可，例如 `D:\Tools\CacheMainDesktop\`。
注意 `%APPDATA%\CacheMainDesktop\` 本身已经是 ASCII，所以**运行期数据（连接、指标、Twig 缓存）
始终在纯英文路径下**，应用放在中文路径也不会污染数据目录。

### 3. 打包目录是就地覆盖的

`dist\win-unpacked\` 里 exe 的时间戳（16:50）早于 `app.asar`（17:26），
说明改完代码后是**直接覆盖**了 `dist\win-unpacked\`，并没有重新生成 `dist\CacheMainDesktop 1.0.0.zip`
（该 zip 当前不存在）。想让磁盘上的 exe 与源码严格对应，重跑一次 `npm run dist` 即可。
